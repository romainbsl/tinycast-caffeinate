= tinycast-caffeinate
:toc: left
:toclevels: 2
:icons: font

[.lead]
A https://github.com/abue-ammar/tinycast[Tinycast] extension (Raycast format) that drives `caffeinate`, most notably with a *Mac awake, display off* mode.


== Commands

[cols="1,3"]
|===
| Command | What it does

| Caffeinate — Display Off
| Keeps the Mac awake and turns the display off (`pmset displaysleepnow`) after a short delay.

| Caffeinate — Keep Awake
| Keeps the Mac awake; the display follows its usual settings.

| Caffeinate — While Process Runs
| Filterable list of your processes.
↵ keeps the Mac awake as long as the process runs (`-w`), ⌘↵ does the same and turns the display off.

| Stop Caffeinate
| Stops the session started by the extension.

| Caffeinate — Menu Bar
| Filled or empty cup icon, mode, remaining time, _Stop_, and start menus for 15m / 30m / 1h / 2h / unlimited.
|===

The first two commands take a *duration* argument, left empty for unlimited: `30m`, `2h`, `1h30`, `90s`, `1.5h`, `45` (minutes).
The maximum is 7 days.


== Preferences

* *-i*, *-s*, *-m*: flags passed to `caffeinate`, all checked by default (`-ims`).
If all three are unchecked, `caffeinate` applies its own `-i`.
The extension never sends `-d` or `-u`.
* *Display Off Delay*: 1 s by default (0 to 30).
It prevents releasing the Return key from waking the display right away.


== Installation

1. Tinycast → Settings → Extensions → enable extensions (disabled by default).
2. Build, then add the `build/` folder:
+
[source,bash]
----
npm install
npm run build        # ray build -e dist -o build
----
+
Settings → Extensions → _Install New_ → _Add from folder_ → pick `build/`.

Tinycast has neither `ray develop` nor hot reload: after every change, rebuild and reinstall from the folder.

WARNING: Never run `ray build` without `-e dist`: it would install into a local Raycast instead of producing `build/`.


== Development

[source,bash]
----
npm test            # unit tests (node:test via tsx): durations, flags, processes, session model
npm run typecheck   # tsc --noEmit
npm run check       # both
----

The pure logic lives in `src/lib/` and is tested; `session.ts` and `actions.ts` hold the side effects and are checked by hand (see <<manual-testing>>).


== Behaviour worth knowing

* *A single tracked `caffeinate`.*
The extension remembers the PID it started and only signals that one, after checking it really is a `caffeinate`.
Your other `caffeinate` processes (terminal, other apps) are never touched.
Starting a new session replaces the previous one.
* *Session lock.*
Whether turning the display off locks the session depends on your macOS settings (Lock Screen); the extension does not change that.
* *Turning the display off.*
The wait and the `pmset` call are handed to a detached `sh`: Tinycast destroys the JavaScript context when a command finishes or its window closes, which would cancel an internal timer.
The result of `pmset` is therefore not observed.
* *Process list.*
Only your own processes are listed (`ps -x`), not the system ones.
* *Process already gone.*
If the chosen process exited between the list being shown and the selection being confirmed, the extension reports it instead of assuming the session is active.
* *Menu bar.*
It refreshes every 10 s (the Tinycast minimum) and each time the menu is opened.
After an action from the command palette, the extension requests an immediate refresh of the icon.


[#manual-testing]
== Manual testing in Tinycast

1. _Display Off_, no duration: the display turns off after ~1 s.
On wake, `pmset -g assertions` shows `PreventUserIdleSystemSleep` without `PreventUserIdleDisplaySleep`.
2. _Keep Awake_ with `1m`: the assertion goes away after one minute; the icon switches back to empty.
3. _While Process Runs_ on a `sleep 60` started in a terminal: `caffeinate` stops with it; ⌘↵ also turns the display off.
4. Start a `caffeinate` by hand, then _Stop Caffeinate_: only the extension's one is stopped.
5. Invalid duration (`abc`): error message, nothing is started.
